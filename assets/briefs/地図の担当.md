頼むこと：下の「ユーザーの答え」（ヒアリング）から、講座フォルダ `{course}/` と `{course}/00_README.md`、全体の地図を作る。先に `python "{skill}/scripts/guide.py" course 2` と `guide.py course 3` を読む。雛形は `{skill}/assets/course/README.md`。
- 各回に**ねらい**を1つ（`python "{skill}/scripts/story.py" --aims` の一覧の言葉のまま。回の言えるようになることに合うもの）。設計の担当は、ねらいの既定の話の型で筋を組む
- 地図は上の段：各回の題・ねらい・ゴール（言えるようになること）・中身の話題・学習者への橋渡しまで。**数値・版・年・件数などの具体の事実は書かない**（各回の設計で裏を取る。どうしても書くなら「（未確認）」を付ける）
- README の「テーマへの詳しさ」は、段の名前と学習者の像の一言で書く（例：`多少知っている（物理の学部の授業まで。テーマの小分野は知らない）`。段の像は雛形のその行）。ユーザーの答えが学習者の説明（「〇〇を習った人」など）なら、その説明から段を選ぶ
- 作業フォルダは作業ディレクトリ直下の `_work/{course}_0N/`（講座フォルダの中に作らない）。この担当はまだ作らなくてよい
- **終えたら** `python "{skill}/scripts/next_step.py" {course} --short` を走らせ、出た「次：」の行を、そのまま返答の最後の行に書く（メインは、それを見て次の担当を起動するか、地図をユーザーに見せる）
返すもの：地図の短い表（回・題・中身・橋渡し）と、迷った所
