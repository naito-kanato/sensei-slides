## 0. 方針

- **模式図として伝わりやすさを優先する。** 飾りより「何が起きているか」が一目で分かること。
- **立体的な描き方は使ってよい。** 円柱の容器や配管、板の上の原子層などは立体のほうが分かりやすい。
- **やめるのは「くどい表現」：** 陰影をつけまくる、光沢（球の白いハイライト）、グロー（発光）、
  グラデーション背景、主張の強い太い輪郭線・装飾線。いわゆる「AIっぽい」絵の質感は避ける。
- **matplotlib＋figkit で描いた図の質感が基準。** 見本の図（`examples/zemi/figs.py`・`examples/course/_work/AI活用講座_01/figs.py`）と
  `figure-style-examples.jpg` に合わせる。迷ったらその水準・質感に寄せる。

## 1. 何を図にするか（最優先の基準）

**目的は聞き手の理解度を上げること。そのスライドで、図にしたときに理解が最も増えるものを選ぶ**。

- **基本はテーマ（＝青帯のまとめ文・赤字の結論）の視覚化。** たいていはこれが一番効果が大きい
- **ただし、一部の内容がひどく難解なときは、その難所を図で示すほうを優先してよい。**
  文字だけだと聞き手がつまずく部分（抽象的な仕組み、直感に反する現象、空間的な配置、何段もの因果、式の各項の意味）は、
  テーマより図の効き目が大きいことが多い
- **数値を2つ以上比べる枚は、まずグラフ（棒・折れ線）を考える**。研究の結果・統計の数値を文字の箱に並べても、差はひと目では伝わらない
- 迷ったら、候補ごとに「文字だけで説明したときの分かりにくさ」×「図にしたときの分かりやすさ」を比べ、差が大きいほうを選ぶ

手順
1. 先に青帯の一文を決める
2. 候補を2つ挙げる：①テーマを見せる絵（比較・変化・傾向・極小・ずれ・範囲）、②そのスライドで一番難しい箇所を解く絵
3. 聞き手の理解がより増えるほうを選び、1b の表から種類を決める。どちらも描けないときは位置づけの図（全体像・分類・流れ図）
4. 飾りの図（雰囲気のイラスト、本文と対応しない写真）は置かない
5. **流れ図は、順番や枝分かれに意味があるとき（手順・因果・分類）だけ**。本文の箇条書きを箱に入れて矢印でつないだだけのものは、流れ図ではなく言い換え。**流れ図は本文4枚に1枚まで（最低2枚）**。超えるなら、テーマか難所を見せる図（模式図・グラフ・位置関係）に変える。どうしても要るなら、設計メモ・構成案に「流れ図の理由：…」を書く（以前の試験で、本文11枚のうち8枚が「書類 → 非常用品 → 荷物を固定」のような流れ図になった。設計メモ・構成案の確認が △ を出す）
6. **スライドの型を内容で選ぶ**（下の表）。「左に文・右に図」が続くと、どの枚も同じに見える。**同じ型は4枚まで**
   （5枚以上続くと、渡す前の確認が △ を出す）。型を変えることが目的ではない。内容の形（比べる・1つの値・横長の図）に合う型を選ぶ

   | 型 | 使う内容 | 部品 |
   |---|---|---|
   | 左に文・右に図 | 文と図を一緒に見せる。結果の説明（基本の型） | `s.p(...)` ＋ `s.image(..., x=7.5)` |
   | 上に文・下に横長の図 | 横長のグラフ・時系列・2枚並べた図 | `s.figure_below(path, caption=...)` |
   | 全面の図 | 図そのものが主張（写真・結果の全体像）。本文は書かず、言うことはノートに | `s.full_figure(path, caption=...)` |
   | 2つを並べて比べる | 手法の比較・前と後・長所と短所 | `s.compare(("A", [...]), ("B", [...]))` |
   | 大きな数字・結論 | 一番伝えたい値・結論を1つだけ（1回のデッキで1〜2枚まで） | `s.key_message("5.1σ 以上", "偶然の雑音なら20万年に1回未満")` |
   | 表が主役 | 複数の候補を複数の基準で比べる（5列×7行まで） | `s.table(...)` |
   | 流れ図 | 手順・因果・分類（本文4枚に1枚まで） | `s.flow(...)` |
   | 区切り | 話の切り替え（独立した話が4つ以上の長い発表で） | `deck.section(2, "結果")`（全面の色）か `deck.title_slide([...])` |
   | 並列カード・格子 | 同格の要素を2〜4個（格子は4〜6個） | `s.cards(items)`・`s.cards(items, layout="grid")` |
   | 段違いの順序・循環 | 段階のある手順・繰り返し（流れ図の数に入る） | `s.cards(items, layout="steps")`・`layout="cycle"`（4枚） |
   | ツリー | 分類・階層 | `s.tree("大分類", [...])` |
   | 前後 | 従来と改善を並べ、差を1つの数で | `s.before_after((…), (…), value="…")` |
   | 2つ並べた図 | 条件の違う2つの図を並べ、下に数値 | `s.pair(a, b, labels=[…], values=[…])` |

   型の辞書（本文の形も含む。いつ使うか・部品）は `references/structures.md`。図の注目点への吹き出しは `s.callout(点, 箱の位置, "解釈")`

   目安の出典：「同じレイアウトが4枚続いたら1枚変える」（Zoho Show の25の手引き）、型の使い分け（deckary の解説、伝わるデザイン）
7. **本文のスライドには必ず何かを見せる。文だけの枚は作らない**（図の案の「なし」も、渡す前の確認も ✘）。描く物が無いなら、数値は大きな数字、2つの違いは比較、手順は表か流れ図にする。どれにもならない枚は前後の枚にまとめる
8. **図は枠ではなく絵そのものを大きく描く**。右に置く図は幅4.5〜5in・高さ3〜4in を埋める。大きな枠の中に細い線1本・小さな箱2つ、では小さい図と同じ。
   描画の検査が、画像の白でない部分の外枠で測り、スライドの8%未満なら「図が小さい」、横の図の下から帯まで2.5inより空けば「図の下が空いている」を出す。
   描く物が少ないなら、値・具体例・名前を図に足す（停止距離なら、速度ごとの距離の棒にする、など）
9. **図は図の案どおりに描く**。描いてみて変えたいときは、先に図の案（設計メモの5節／構成案の「図で見せるもの」）を直し、理由を書く。渡す前の確認が、図の案とスライドの図の種類を突き合わせる

あわせて守ること
- 推測の多い概略図になるなら無理に作らない。根拠のある図で説明できる候補を選ぶ
- 図の中の赤（強調）は、本文の赤字や、図で説明している箇所と対応させる（図と文で強調がずれないように）
- 確認：**この図があることで、聞き手が本文だけより速く・確実に分かるか**

見本の例（ゼミ＝`examples/zemi/`、講座＝`examples/course/`）
- テーマを見せた例：ゼミ2枚目 `f_strain`（「重力波は時空のひずみの横波」を、輪に並べた粒子が縦横交互に伸び縮みする絵で見せる）、
  講座3枚目 `f_fabricated`（「自然な文でも、事実と違うことがある」の根拠を、実在しない文献の割合の2本の棒で直接見せる）
- 難所を見せた例：講座2枚目 `f_next_token`（「次の語の確率を計算している」という抽象的な仕組みを、「明日の天気は」の次の候補と確率の横棒で具体的に）
- 仕組みの図で十分だった例：ゼミ4枚目 `f_michelson`（腕の長さの差を読む仕組みを、論文の図をもとに共振器などを省いた干渉計の模式図で）
- 論文の図を使った例：ゼミ5〜7枚目（話すパネルだけを切り出す。結果③は注目点に `s.oval` の赤い輪）
- 位置づけの図が妥当な例：講座4枚目（答え → 出典 → 一次資料 → 使う／要確認 の流れ図。PowerPoint の図形で）
- 過去のデッキでの作り直しの教訓：
  - 最初の版で、話題の基本グラフをそのまま置いた図が3枚あった。どれも「話題の図」で、結論や難所を見せていなかった
  - 構成案レビューで、教科書外の数値に頼る図を減らした（教科書外の値の一覧の図は削除、確かでない目盛りの数値は外した、
    形が教科書にない曲線は、教科書が述べている対比の図に置き換えた）
  - テーマを描くと、教科書の数値が1つだけで推測の多い概略図になるスライドは、仕組みの図（回路図）のまま採用した（ユーザーの判断）
  - 結論が「〜まで測れる」のような数値だけのスライドは、装置図で位置づけを補った

## 1b. 図の種類の選び方

**図は目的から選ぶ**：構成案・設計メモの「図で見せるもの」は **「目的：種類：中身」** で書く（「比べる：棒グラフ：認定率を病床規模の7区分で」）。先に目的を下の表から1つ選び、その目的のおすすめの種類から図を選ぶ（先頭がいちばんのおすすめ）。**数字の比べを描くときは、中身にデータを指す**（「比べる：棒グラフ：データ1」。講座は設計メモ3b節のデータ、カードがその表を書き手に写す）。グラフの形はデータの形で決まる：区分どうしを比べる → 棒、時間で変わる → 折れ線、全体の中の割合 → 帯、1つの驚く数 → 大きな数字。おすすめ以外にするなら、中身に「外す理由：…」を書く。check_outline・check_memo が、目的が無い・種類が選択肢に無い・おすすめでない（理由なし）を △ にする。レビュー担当も、目的と図が合っているかを見る。

| 目的 | 何をしたいとき | おすすめの種類 |
|---|---|---|
| 比べる | 2〜8個の値を比べる・順位 | 棒グラフ・比較（2つだけのとき）・表 |
| 推移 | 時間・条件で値が変わる | 折れ線・概略グラフ |
| 傾向 | 関数形・傾向を見せる（数値なし） | 概略グラフ |
| 内訳 | 全体の中の割合 | 帯グラフ・大きな数字 |
| 時期 | いつ何が起きたか・時代の区切り | 年表 |
| 仕組み | 仕組み・構造・配置・縮尺 | 模式図・資料の図 |
| 流れ | 手順・因果・分類の枝分かれ | 流れ図 |
| 観点 | 項目×観点で整理する | 表 |
| 違い | 2つの状態・方法の違い | 前後・比較 |
| 並び | 同格の要素を並べる | カード |
| 階層 | 上下関係・分類の木 | ツリー |
| 印象 | 1つの値・結論を印象づける（1回に1〜2枚） | 大きな数字 |
| 柱 | 答えを支える柱の一覧（答えの位置「先」の答えの枚） | カード・ツリー |
| 実物 | 資料の図・実物をそのまま見せる | 資料の図・写真 |

種類ごとの部品：数値を2つ以上比べる・割合・時間の変化を、文字の箱や表だけで書かない（棒グラフ・帯グラフ・折れ線・年表を先に考える）。

| 名前 | 目的 | 部品 |
|---|---|---|
| 棒グラフ | 2〜8個の値を比べる・順位 | `figlib.bars`（主役だけ青、値を棒の先に） |
| 折れ線 | 時間・条件で値が変わる（数値あり） | `fig()` に plot（`figlib.data_fit`） |
| 概略グラフ | 関数形・傾向（数値なし） | `fig()` ＋ `noticks()`（`figlib.compare` など） |
| 帯グラフ | 全体の内訳・割合 | `figlib.share_bar` |
| 年表 | いつ何が起きたか・時代の区切り | `figlib.timeline`（主役の出来事だけ赤。出来事と時代の帯で3つ以上。2つ以下なら本文の1行か表） |
| 模式図 | 仕組み・構造・配置・縮尺 | `blank()` に `box`・`arrow` など |
| 流れ図 | 手順・因果・分類（順番や枝分かれに意味がある） | `s.flow`（PowerPoint の図形） |
| 表 | 項目×観点 | `s.table` |
| 比較 | 2つを左右に並べて違いを見せる | `s.compare` |
| 前後 | 変える前と後 | `s.before_after` |
| カード | 同格の要素を2〜6個 | `s.cards` |
| ツリー | 階層・分類の木 | `s.tree` |
| 大きな数字 | 1つの値・結論を印象づける（1回に1〜2枚） | `s.key_message` |
| 資料の図 | 教科書・論文の図をそのまま（出典を付ける） | `pdf_pages.py crop` |
| 写真 | 実物（自作しない） | ユーザーに用意してもらう |

下の表は、資料の種類から見た描き方の細部。

| 伝えたいこと | 図の種類 | 作り方 | 参考 |
|---|---|---|---|
| 教科書・論文に図がある | 教科書・論文の図 | `pdf_pages.py crop`。注目点は PowerPoint 上で赤丸・赤矢印を重ねる | ゼミ7枚目（Fig. 4 右の注目点に赤い輪） |
| 関数形・条件による変化の傾向 | 概略グラフ（目盛りなし） | `fig()` ＋ `noticks()`。式から計算して描く | figlib の `compare`・`decompose`・`tangent` |
| 具体的な数値がある | 棒・データ点＋補間、目盛りあり | 点は赤丸、曲線は青。値をラベルで添える | `f_fabricated`、`f_next_token`、figlib の `data_fit` |
| 装置・配置・構造 | 断面の模式図 | `blank()` 上に線・`box()`・`cylinder()` | `f_michelson` |
| 粒子・状態のイメージ | 平らな円の配置 | `particles()`・`draw_disks()`。注目粒子だけ赤 | `f_strain`、figkit の `disordered_disks` |
| 流れ・手順・因果 | ブロック図 | 箱と矢印だけなら **PowerPointの図形**（`s.flow`、`s.rect`＋`s.arrow`）で描くと後で編集できる。図中に組み込むなら `box()`＋`arrow()` | 講座4・9枚目（学習の2段階、確かめる手順の流れ図） |
| 2つ以上の比較 | 表 | `s.table()` | ゼミ14枚目（Table I の推定値） |
| ベクトル・角度分布 | ベクトル図・極座標の形 | `blank()` に矢印と曲線 | figlib の `precession`・`polar_pattern` |
| 時間信号・スペクトル | 波形 | `fig()`、目盛りなし | ゼミ8〜10枚目（論文 Fig. 1・2）、figlib の `decay_signal` |
| 実物（天体・鉱物・装置写真） | 写真 | 自作しない。ユーザーに画像を用意してもらう | — |

## 2. 描き方のルール

### 色（`figkit.COL`）
- 主役の線・濃い液体 = `blue`（215F99、テンプレートの青帯と同じ色）
- 流れ・補助の線・粒子 = `lblue`（4E95D9）
- **強調 = `red`。1つの図で1〜2か所まで**（注目粒子、極小点、結論に関わる線）
- 比較対象・参考線 = `gray` の破線（「単純なモデル」「補正なし」など）
- 塗り：液体・冷たい側・範囲の網掛け = `pale`、熱い側 = `warm`、試料・金属ブロック = `sand`
- 慣例をそろえる：熱い側は赤系・冷たい側は青系。同じものは全部の図で同じ色にする
- 1つの図に使う色は4色まで

### 線（`figkit.LW`）
- グラフの主線 2.5pt、模式図の輪郭は **1.5pt以下**、引き出し線・補助線は 1pt
- 球や粒子に黒い輪郭を付けない（`ec="none"` の平塗りが基本）。箱は細い輪郭か輪郭なし
- 矢印は細身（`arrow()`）。太いブロック矢印はスライド側の `s.arrow()` だけで使う

### 立体
- OK：円柱・管・板を「楕円＋直線」で描き、平塗りする（`cylinder()`）。液面は楕円で示す
- OK：板の上の原子層のような斜めから見た配置。粒子は平らな円で、色の濃淡は2段階まで
- NG：球の白いハイライト、放射状のグラデーション、落ち影、発光、背景のグラデーション、テクスチャ

### 文字
- **基本は 14pt**（スライド上の実寸。本文20ptより小さく、12pt が最小。13pt 未満は `figkit.save` が WARN）。
  12pt を既定にすると、置いたときに少し縮むだけで読めなくなる（過去の質問回答デッキで全図12pt→実寸11.5ptになった）。
  `figkit` の既定（font.size 15、軸ラベル16、目盛13）をそのまま使い、`fontsize=` で下げるのは重なりを避ける1〜2か所だけ
- **描いた大きさのまま置く。** `s.image(path, x, y)` と**幅を渡さずに**置くと、画像の dpi から描いた幅（`fig(w, h)` の w に
  余白が少し足された値）で置かれる。`w=` で拡大すると図の文字が本文と同じ大きさになり（×1.2 で 14pt → 17pt）、縮めると読めなくなる
  （`check_layout.py` が「図の縮尺」を出す。×0.95 未満と ×1.05 超は直す。図が入らないなら本文を削って図の場所を確保する）
- **文字を枠の縁や線にかけない**：箱の中の文字は、縁との間に文字の高さの半分ほどすき間を取る（入らなければ箱を広げるか改行する）。弧・矢印・線の横のラベルも、線から離して置く。`figkit.save` が、文字が枠の縁・線・矢印にかかっていると WARN を出す（以前の講座で、箱の中の「ドライヤー」が縁からはみ出し、「フード」の文字が弧に重なった）。
- **図は必ず `figkit` の `save` で保存する**（`fig.savefig` を直接呼ばない）。save が上の検査をするので、直接保存すると検査が走らない。渡す前の確認（`check_done.py`）が figs.py を見る。
- **1つの図にラベルは5個まで**（4文字以上の文の数。`figkit.save` が WARN）。説明を全部図に書かず、本文かノートで言う。
  ラベルが6個以上必要なら、図を2枚に分けるか話題を絞る
- ラベルは対象のすぐ横に直接書く。凡例は使わない。離れる場合は `callout()` の細い引き出し線
- **ラベルは名詞だけ**（`f_michelson` の「レーザー」「検出器」「鏡」、`f_strain` の「波の前」「1/4 周期後」）。
  「ここで腕が伸びて信号が強くなる」のような説明文を図に書かない。
  説明は本文かノートに置く。文のラベルは長くなって必ず線や曲線と重なる（過去の質問回答デッキの図で、説明文のラベルが線と重なった）
- **ラベルと線が重なったら、線を動かさずラベルを動かす。** 置き場所は、曲線の外側（凸の反対側）、軸の端、空いている隅の順に探し、
  それでも無理なら `bbox=dict(fc="white", ec="none", pad=1)` で白く抜く（最後の手段。線が切れて見える）
- 記号は本文と同じにする（$h$, $L_x$, $\Delta L$, $\rho$ …）。日本語と `$数式$` の混在は figkit の設定のままでOK
- 定性図は目盛りを消す。「（概略）」「確率は例」の断り書きは図に入れず、スライド側の `s.caption()` で付ける
- 図番号・図のタイトルは入れない（スライドの見出しと青帯が役目を果たす）
- **見出し＋説明の箱は、説明を全角1字下げて左揃え**（階層の差が見える）：`box(ax, x, y, w, h, text="説明", head="見出し")`。
  PowerPoint のカード（`s.cards`）と場合分けの部品も、説明を1字下げて組む。中央揃えの箱（1語のラベル）はそのまま

### 物理の正しさ
- 形は式から計算して描く（例：成分と和の図は各成分の式から数値で足す、資料の数点は経験式の形で補間する、
  `f_strain` の伸び縮みは輪の座標に縦横の倍率を掛けて描く）。手で曲線を描かない
- 漸近形・べき・極小の位置・単調性が正しいかを確認する
- 教科書外の数値は確信のあるものだけ。入れたら必ず断り書きを付け、発表者ノートにも出典の性格を書く
  （`f_next_token` の確率は説明のための例なので、スライドに「（概略・確率は例）」と書いた）
- 見やすさのために誇張したとき（傾斜角を大きく描く等）は、図中かノートでそう分かるようにする

## 4. レシピ集（見本の `figs.py` と figkit の小道具）

図スクリプトの書き方（`def f_<名前>()` を並べ、`python figs.py <名前>` で一部だけ描き直す）は、次の2つの見本を雛形にする。

| 関数 | 見本 | 図 | 使っている技 |
|---|---|---|---|
| `f_strain` | `examples/zemi/figs.py` | 輪に並べた粒子の伸び縮み（3コマ） | `blank()` に3コマを横に並べる。元の輪は灰の破線、粒子は青の平塗り（`scatter`、輪郭なし）、下に名詞のラベル |
| `f_michelson` | `examples/zemi/figs.py` | マイケルソン干渉計の模式図 | 光路は赤の実線、検出器への光は破線、鏡は `Rectangle` の淡色（pale）。腕の長さは `arrow(..., style="<\|-\|>")` の寸法線＋数式ラベル。論文の図から省いた部品は docstring とスライドの注記に書く |
| `f_next_token` | `examples/course/_work/AI活用講座_01/figs.py` | 次の語の候補と確率（横棒） | `fig()` に `barh`。主役の1本だけ青、ほかは灰。値は棒の右端に直接書く（凡例なし） |
| `f_fabricated` | `examples/course/_work/AI活用講座_01/figs.py` | 実在しない文献の割合（2本の棒） | 比べる2本を赤（結論に関わる側）と青に。値ラベルを棒の上に、出典は docstring と原稿の ※ 行に |

`figkit` の小道具：`fig`（グラフ用、上と右の枠なし）、`blank`（模式図用、座標がインチ）、`save`（220 dpi で保存し、文字の大きさとラベルの数を検査）、
`arrow`（細い矢印・寸法線）、`box`（角丸の箱）、`callout`（囲みラベル＋引き出し線）、
`particles`（平塗りの粒子）、`cylinder`（平塗りの円柱・液面つき）、`coil`（ソレノイド）、`noticks`（概略図の目盛りを消す）。
原子配置の部品：`disordered_disks`（乱れた円盤配置＝液体・ガラス。`cache=` で再利用）、`tri_lattice`（三角格子＝結晶）、
`draw_disks`（平塗りの円を枠で切り取って並べる）、`random_network`（ボロノイ図から作る2Dの連続ランダム網目）。

過去の講座の図で使った型のうち、スキルに汎用化済みのもの：乱れた円盤配置（液体・ガラス）は
`figkit.disordered_disks`、三角格子（結晶）は `figkit.tri_lattice`、円を枠で切り取って並べるのは `figkit.draw_disks`、
2Dの連続ランダム網目は `figkit.random_network`。
汎用化していない例（スキルには含まれない）：
配置から回折パターンを計算、同じ配置で動きだけ変える3コマ、同じ軸・同じ色の図を回をまたいで積み上げる、
破線に沿わせて回転したラベル、網目の一部の辺だけを切ってイオンを置く、インチ単位で描く色見本の1行
（凡例の代わりに粒子の色を名指しする）。同じ形が要るときは、この説明を手がかりに figkit の部品で描き直す。

## 4b. 図の型（`figlib.py`）と、これまでの図のカタログ

これまでのデッキで描いた図のうち、話題が変わっても使える形を `figlib.py` に関数としてまとめてある。
どれも `ax` に描くだけなので `fig()` / `blank()` と組み合わせ、ラベル位置は呼び出し側で調整する。
見本：`python <skill>/scripts/figlib.py --demo <出力フォルダ>`（各型のサンプル図を書き出す）。

| 型 | 使いどころ | 向く図の例 |
|---|---|---|
| `compare` | 主役（青実線）と比較対象（灰破線） | 理論と単純なモデル、2つの物質の温度変化の対比、補正の前後 |
| `decompose` | 成分（破線）とその和（青実線） | 寄与の足し合わせ（一定の成分＋変化する成分） |
| `tangent` | 1点での接線と傾きの意味 | 感度・分解能（曲線の傾き）、グラフの傾きから量を読む |
| `extrapolate` | 直線を x→0 へ点線で外挿、共通の切片を赤丸 | 測定の極限値（条件を0に近づけた値） |
| `data_fit` | 資料の数値（赤丸）＋（対数）空間の多項式補間＋値ラベル | 資料にある数点と経験式の補間 |
| `range_bars` | 名前つきの範囲を横の両矢印で並べる（片側開放も可） | 手法・目盛りごとの有効範囲の一覧 |
| `equal_area_peaks` | 面積が同じローレンツ形で線幅とピーク高さ | スペクトルの線幅と高さ、雑音の線幅 |
| `polar_pattern` | 角度分布 W(θ) を極座標の形で | 放射・散乱の角度分布 |
| `precession` / `decay_signal` | 歳差運動のベクトル／減衰振動と包絡線 | 回る磁化・こま、減衰する信号 |
| `dipole_lattice` | 格子上の双極子、1つを強調して周りの寄与 | 周りの双極子がつくる場 |

**これまでの図のカタログ**：`python <skill>/scripts/catalog.py _work _work/figure-catalog` で、全デッキの `figs/*.png` を
デッキごとに並べた一覧（各図の下に元の関数名）ができる。新しい図を描く前に見て、同じ話題・同じ形の図があれば流用する。

スライド上の部品（`zemi.py`）：箱と矢印の流れ図は `s.flow([...], x, y, w, direction="down"|"right", arrow_labels=[...])`、
比較表は `s.table(...)`、図の注記は `s.caption(box, "...")`。

`figure-style-examples.jpg` は、新しい見本の図（重力波：`f_strain`・`f_michelson`、AI講座：`f_next_token`・`f_fabricated`）と
figlib の型の見本（`figlib.py --demo` の出力）を並べたもの。目指す質感（平塗り・細い線・名詞のラベル・赤は1〜2か所）の基準にする。

## 5. 作業手順とチェックリスト

0. **描く前に下書き**：`python <skill>/scripts/figdraft.py <work>` の雛形を埋めて、図の関数の説明（docstring）の頭に書く。模式図は「実物（箱に文字を入れた物でなく、粒子・容器・光路などの形）・気づく（見た人が気づく1点）・配置・ラベル」、グラフは「気づく」（目立たせる差。その棒・点を強調の色に、ほかは灰色）
1. `figs.py` に `def f_<名前>():` を並べる。1関数1図、スライドに置く実寸で作る
2. `python figs.py <名前> ...` で一部だけ再生成（引数は関数名から `f_` を除いた部分。出力ファイル名ではない）
3. `python <skill>/scripts/figgrid.py figs render/figs_grid.jpg [名前 ...]` で一覧にして 【画像を見る】で見る
4. 一覧で次を確認し、直したら 2→3 をくり返す
   - [ ] 下書きの「気づく」が一目で分かる（比べの相手が同じ図にある・強調の色がそこだけ）。模式図は下書きの「実物」の形が描けている
   - [ ] その図があることで、聞き手が本文だけより速く・確実に分かる（テーマか難所のどちらかを確かに助けている）
   - [ ] 文字が□になっていない
   - [ ] ラベルが線・点・軸ラベル・ほかのラベルに重なっていない（一番多い失敗）。
         確かめ方：一覧画像を【画像を見る】で見て、ラベルの文字列を1つずつ目で追い、文字の上を線が通っていたら直す。
         「だいたい見えている」で通さない（過去の質問回答デッキは3枚の図で重なったまま渡して指摘を受けた）
   - [ ] ラベルが名詞だけで、説明文（「〜が弱い」「〜できない」）になっていない。ラベルは5個まで
   - [ ] 模式図で文字が線を横切っていない
   - [ ] 光沢・影・グラデーション・太い輪郭が入っていない
   - [ ] 赤は強調の1〜2か所だけ、色は4色以内
   - [ ] 記号・数値がスライド本文と一致している
   - [ ] 形が物理的に正しい（漸近形・極小・単調性）
   - [ ] `figs.py` の実行時に `figkit.save` の WARN（13pt 未満の文字、ラベル6個以上、文字が枠の縁・線にかかっている）が出ていない
5. スライドに置いたら `check_layout.py` の一覧の「図の縮尺」が ×0.95 以上（描いた幅のまま置いている）で、
   `render_check.ps1` の画像で図の文字が本文より一回り小さい程度（14pt 前後）に見えることを確かめる
