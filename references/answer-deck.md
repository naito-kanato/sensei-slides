# 原稿へのコメント（疑問点）に答える — 質問回答デッキ（SKILL.md 手順8）

ユーザーが原稿HTMLで疑問点をコメントし、「書き出し」して「コメントした」と言ったら、**別の新しいデッキ**
（`<資料名>_質問回答_スライド.pptx`・`<資料名>_質問回答_原稿.html`）を作って答える。元のデッキには足さない。
**質問回答デッキ自体へのコメント**（`<資料名>_質問回答_コメント.json`）には、同じ質問回答デッキの末尾に区切りのスライド
（`deck.title_slide([T], subtitle="追加の質問への回答（コメントN件）")`）を入れて回答を足す（別のデッキは作らない）。

- オプション表は貼るだけで質問は省く（値は元のデッキと同じ。SKILL.md 手順0）
- **モデル**：回答の方針（`answers.md`）は【上位モデル】が書く（講座は必ず。`references/course.md` 手順6）。
  【標準モデル】で作っていて、答えに**資料外の一般論**が多いときは、build に入る前に `answers.md` を【上位モデル】の【別のエージェント】に読ませて
  事実の誤りと言い過ぎを確かめさせる（ファイルは読むだけ）。資料（講義録）の範囲で答えられるときは不要で、完成後のレビューで足りる

## 流れ

1. **コメントを読む**：ユーザーが保存場所を言わなければ `python <skill>/scripts/comments_read.py --find` で候補を見る
   （ダウンロードフォルダと作業フォルダ以下の `*_コメント*.json` を新しい順に表示するだけで、移さない）。
   チャットに「文章でコピー」の形で貼られたらそれも使う。読むと決めたファイルを
   `python <skill>/scripts/comments_read.py "<json>" --out <work>/質問回答/comments` で作業リストにする
   （このとき、ダウンロードにある同じ講座IDのコメントが README の保存先へまとめて移る）。
   スライドの範囲へのコメントは切り抜きPNG（囲んだ範囲に赤枠）ができるので、【画像を見る】で見てどこを指しているか確かめる。
   文章へのコメントは【】が選んだ部分。元の原稿（notes.md）と資料の該当箇所も読む。
   確認問題への答え（「1-1 への答え」、または問題番号の上に置いた範囲コメント）は、資料の模範解答と比べて**添削**する
   （○／△／×と、足りない要素・用語の直し。問題3つずつ1枚、元のデッキの問題の区切りに合わせる）。
   添削スライドには**元の問題文も載せる**：表「問題｜あなたの答え｜判定と補足」（行ラベル＝問題番号、14pt、セル内は手で改行）。
   原稿も「1-3 は『…』という問題でした。あなたの答えは…」と問題から読む
2. **回答の方針を決める**（作業フォルダ `<work>/質問回答/` に `answers.md`。`assets/answers/answers.md` の表の形：1行＝回答スライド1枚、
   コメント・元の枚の列つき。表にしておくと `scaffold.py <work>/質問回答` が骨組みと、枚ごとのカード（答えるコメント・元の枚の原稿・回答の書き方）を作り、
   回答の本文と原稿を書き手に1枚ずつ任せられる。カードは軽いモデルに書かせるときだけ使う。標準以上のモデルなら表と骨組みから直接書く）：コメントごとに「何がわからないのか」を一文で言い直し、
   資料で確かめた答え・資料外の補足（明記する）・必要な図を決める。同じ点への複数のコメントは1枚にまとめ、答えが長いものは2枚に分ける。
   コメントが元のスライドや原稿の誤り・説明不足を突いているときは、元のデッキも直す（直したことを回答スライドに書く）
3. **デッキを作る**：`<work>/質問回答/build.py`。タイトルは元のデッキと同じ（例「第3回 粘度という物差し」）、表紙のサブタイトルは「質問への回答」。
   1枚の形：●見出し＝質問の要約、本文1行目に `{c:← N枚目「選んだ部分」}`（範囲コメントなら `{c:← N枚目の図の○○}`）とコメントの要旨、
   続けて答えの要点（2〜4個、赤字は結論）、右に図（元のスライドの図を再利用するか、答えのための模式図を新しく描く）、
   青帯＝答えの一文。最後に「まとめ：今回の質問から」を置いてもよい（水増しはしない）。
   **答えも本文と同じ体言止め**で書く。コメントへの返事を会話文で書かない（「合っています。正確には〜の速さ比べです」→
   「合っている：冷却と結晶化の速さ比べ」、「Na は方向のある結合を作れない ⇒ 網目の一員にはなれない」→
   「Na：方向のある結合なし ⇒ 網目に入れない」）。
   会話調の答えは原稿（notes.md）に書く。本文は 80〜100字が目安（元のデッキの本文より短く。質問の行が上にあるため）。
   図は答えのための1点だけを描き、説明文をラベルにしない（説明は本文へ、ラベルは名詞だけ）
4. **原稿**：元のデッキと同じモード（発表／AI講義）で `notes.md` に書く。AI講義モードなら「あなたは5枚目の『…』について、…と聞きましたね」で始める。
   ※行で、コメント番号（#3）と元のスライド番号を残す
5. SKILL.md の手順5〜7と同じく描画の検査 → 完成後のレビュー（5b）→ `notes_html.py`（原稿は build.py が notes.md から入れる）→ `check_done.py`。
   何件のコメントに何枚で答えたか、元のデッキを直したかを伝える。
   答え終わったコメントは、ユーザーが原稿HTMLの「一覧」→「全部消す」で消せる（消す前に書き出しておくよう伝える）
6. 講座の回なら、講座の README の「つまずき一覧」に、取り違えたこと・抜けていたことを1行ずつ足す（次の回の設計メモが読む）

## 原稿HTMLのコメント機能（ユーザーに説明するとき・保存先の決まり）

- C キーか、ページ番号バーの右の「コメント」ボタンでコメントモード。原稿の文章を選ぶとその部分に、
  スライドはドラッグで範囲を囲むとそこにコメントできる。確認問題のスライドには原稿の下に「1-1 に答える」ボタンが並び、
  答えを書ける（●見出しに「問題」があり「解答」がないスライドの「1-1　問題文」の枠から自動で作る）
- コメントと答えはブラウザに自動保存され、上部のバーの「書き出し」（コメントボタンの横、常に表示）で `<資料名>_コメント.json` になる
- **保存先は資料フォルダの README（`00_README.md` など）の `- 書き出しの保存先: このフォルダ（…）` の行で決める**。
  **講座ID**も README の `- 講座ID: AI` の行で決め、書き出すファイル名の頭に付く（`01_生成AIは何をしているか` → `AI01_生成AIは何をしているか_コメント.json`）。
  新しい講座の資料フォルダを作ったら、README にこの2行を書く（IDは講座ごとに別の英字）
- ブラウザはページから任意のフォルダへ書けないので、書き出しは何も聞かずにダウンロードフォルダへ保存し、JSON に `save_dir`・`course_id` を入れておく。
  `comments_read.py` でコメントを読むときに、ダウンロードにある**同じ講座IDのコメントだけ**をまとめてその講座の保存先へ移す
  （別のIDのコメントには触らない。読まずに片づけるだけなら `comments_read.py --collect GA`）。
  任意で、一覧の「保存先フォルダを登録」で一度フォルダを許可すると、以後はダウンロードを通さずそこへ直接保存する
- 見た目を確かめるときは Edge のヘッドレスで撮る：
  `msedge --headless=new --window-size=1600,1000 --screenshot=<png> "file:///…/<資料名>_原稿.html"`
  （画像ができずに終わる環境もある。そのときは中身だけ確かめる：答えボタンの数 `grep -o 'data-q="[^"]*"' <html>`、
  講座ID `grep -o 'data-course-id="[^"]*"' <html>`、notes_html.py が表示する「コメントの保存先（README の指定）」の行）
