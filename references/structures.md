# 型の辞書：本文の形と図解の型

スライドは、見た目（テンプレート）だけでなく、**文字の塊の組み方**でも決まる。組み方を AI に任せると、モデルが変わるたびに変わり、
「〜を確認」の箇条書きが並ぶ単調なスライドになりやすい。そこで、構成案（outline.md）・設計メモ（memo.md）の表の **「本文の形」の列** で
枚ごとに組み方を決め、**部品**（zemi.py）で組み、**渡す前の確認**（check_done.py）が部品の名前で突き合わせる。

型は、研究発表のデッキ（ゼミの輪読・論文紹介・学会発表）を1枚ずつ見て取り出したものと、研究発表のデザインの手引き・
公開されたスライドの型の一覧から研究発表に合うものを足したもの。見本は `examples/structures/`（`python build.py`）。
名前と部品の対応は `scripts/structures.py` にある。

## 1. 本文の形（文字の塊の組み方）

1枚に1〜2個。2つなら「ラベル・帰結」のように書く。同じ形の組が5枚以上続いたら、構成案の確認が △ を出す。

| 名前 | 形 | 使う場面 | 部品 |
|---|---|---|---|
| 帰結 | 2〜3行の説明のあと「⇒ 赤字の一言」。塊の最後の行がその塊の結論 | 説明から結果・意味を言う。一番よく使う | `s.lead(["前提1", "前提2"], "帰結")` |
| ラベル | 効果・手法・用語の名前を小見出し（太字）にして、下に1〜2行を字下げ。`then=` で最後に帰結 | 定義・用語を並べる。手法の要素 | `s.block("アトキンス効果：", ["説明1", "説明2"], then=None)` |
| 展開 | 左に条件・前の状態、右に結果・次の状態、間に横の矢印 | 「〇〇すると → △△」「臨界速度以下 → 輸送率は一定」 | `s.develop("左", "{r:右}")`（左右は (ラベル, [行]) でもよい） |
| 縦の結論 | 前提の段（中央ぞろえ）、下向きの矢印、結論（線だけの囲み。下の結論の囲みと見分けられるように） | 背景・問題から目的・結論を導く（学会発表の導入・まとめ） | `s.lead_down("前提", "結論")`（`boxed=False` で赤字） |
| 場合分け | 条件を太字、説明を字下げして、薄い灰の囲みに | 温度域・符号・条件ごとに振る舞いが変わる | `s.cases([("T > T_λ", "説明"), ("T < T_λ", "説明")])` |
| 問い | 「〜ではないのか？」（太字）の下に「⇒ 確かめた結果」 | 考えられる別の説明を1つずつ確かめる・否定する（検証の筋） | `s.ask("〜ではないのか？", "〜により否定")` |
| 想定質問 | 「Q1　質問」（太字）の下に字下げして「⇒ 回答」、1枚に2組（間に細い線） | 発表の最後の想定質問の枚（役割「想定質問」）だけ | `s.qa_pairs([("Q1", "質問", "回答"), ("Q2", …)])` |
| 手順 | 1. 2. 3.（項目の2行目は字下げ） | 解析・試料作成・測定の手順 | `s.numbered(["手順1", "手順2"])` |
| 式の注釈 | 式の右に記号の定義を縦に。式の項に矢印で意味 | 式の各項・記号の意味 | `s.peq(...)` ＋ `s.defs(...)`・`s.pointer(...)` |
| 箇条 | 短い並び | 上のどれにも当たらないとき（多用しない） | `s.p(...)` |

**入れる所**：形を選ぶと、要点を入れる所が決まる。構成案・設計メモの「本文の要点」は、入れる所の書き方で書き、事実（〔出どころ〕・〔事実N〕）はその所に付ける。1か所に入る事実は0個のことも、2個以上のこともある。check_outline・check_memo が書き方を見て（△）、scaffold.py が入れる所どおりに部品の呼び出しを組む。

| 形 | 入れる所 | 要点の書き方（「 / 」で区切る） |
|---|---|---|
| 帰結 | 前提（1〜3）・帰結（1） | `前提〔…〕 / 前提〔…〕 / ⇒ 帰結〔…〕` |
| ラベル | 見出し＋説明（1〜4組） | `見出し：説明〔…〕`（説明の後ろに `⇒ 帰結` も可） |
| 展開 | 左（条件・前）・右（結果・後） | `左〔…〕 → 右〔…〕` |
| 縦の結論 | 前提・結論 | `前提〔…〕 / ⇒ 結論〔…〕` |
| 場合分け | 条件＋説明（2〜3組） | `条件：説明〔…〕` を2つ以上 |
| 問い | 問い＋確かめた結果（1〜3組） | `〜ではないか？⇒ 確かめた結果〔…〕` |
| 手順 | 段（2〜5） | `1. 段 2. 段 3. 段〔…〕` |
| 式の注釈 | 式・記号の意味 | `式（＝を含む）〔…〕 / 記号：意味` |
| 箇条 | 項目 | `項目 / 項目` |

2つの形を組むとき（「ラベル・展開」）は、それぞれの書き方の要点を並べる。どの書き方でもない要点は、骨組みで「入れる所の書き方でない要点」と TODO になる（入れる所に移すか、ノートへ）。

選び方
- **まず内容の形を見る**：結果を言う（帰結）、名前を定義する（ラベル）、条件と結果（展開）、条件ごとに違う（場合分け）、別の説明を退ける（問い）、順番（手順）
- 1つの塊は2〜3行。塊と塊の間は1行ぶん空ける（部品がそう置く）。赤は塊の結論の行にだけ使う
- 設定の一覧（outline.md の `## オプション`）に **「本文の形の割合」**（`analyze_structure.py` で本人のデッキから数えたもの）があれば、その割合に寄せる。
  割合の多い形を基本にし、内容が合うときだけほかの形にする（本人が作ったような組み方になる）
- 「〜を確認」「〜に注意」の言い換えを並べない。帰結の一言には、数値・具体例・確かめた結果を書く

## 2. 図解の型（スライドの型に足すもの）

| 名前 | 形 | 使う場面 | 部品 |
|---|---|---|---|
| 並列カード | 同じ大きさの箱2〜4枚に、見出し（主色の太字）＋1〜2行 | 手法の要素・条件・候補を同格に | `s.cards([("見出し", "説明"), ...])` |
| 格子のカード | 2列か3列の格子（4〜6枚） | 同格の要素が多いとき | `s.cards(items, layout="grid")` |
| 段違いの順序 | カードを階段状にずらし、細い矢印でつなぐ（3〜4枚） | 段階のある手順。流れ図の数に入る | `s.cards(items, layout="steps")` |
| 循環 | 4枚を2×2に、時計回りの細い矢印 | 測定→解析→モデル→次の測定のような繰り返し。流れ図の数に入る | `s.cards(items, layout="cycle")` |
| ツリー | 左に大分類、右に小分類、折れ線でつなぐ | 分類・階層 | `s.tree("大分類", [("小分類", "説明"), ...])` |
| 前後 | 左に従来（灰）、右に改善（薄い主色）、間に矢印、右の下に差を赤い数値1つで | 解析の改善・装置の改良 | `s.before_after(("従来", [...]), ("改善", [...]), value="誤差 1/3")` |
| 2つ並べた図 | 条件の違う2つの図を並べ、上にラベル、下に赤い数値 | 温度・条件の違う2つのデータを比べる | `s.pair(a, b, labels=[...], values=[...])` |
| 吹き出し | 図の注目点から細い線で、薄い主色の箱に解釈 | 結果の図の読み方を言う（1枚に1〜2個） | `s.callout((点x, 点y), (箱x, 箱y), "解釈")` |
| 区切り | 全面を主色で塗り、章の番号と題 | 独立した話が4つ以上の長い発表の章の頭 | `deck.section(2, "結果", lead="…")` |
| 漸進表示 | 同じ枚を数枚。前の項目は灰色、今の項目だけ濃く | 研究の要約・手順を1項目ずつ話す | `deck.build_up(title, heading, items, figure=…)` |

図解の型も「図」に数える（図の無いスライドにならない）。ただし箱に本文を言い換えて入れただけのものは、図ではなく言い換え。
カードの中身は1〜2行の名詞句にし、説明は本文かノートに回す。

## 3. 構造（テンプレート）と色

テンプレートは構造で分ける。色は別に選べる（`deck_options(P, name="テンプレート3", color="深緑")`、一覧の「色」の行。配色は 青・紺とオレンジ・生成りと山吹・藍・青緑・珊瑚・墨と山吹・深緑・グレーと赤・墨と藍）。

| 構造 | 形 | 面積の割り振り | テンプレート  合う本文の形 |
|---|---|---|---|---|
| 結論ヘッダー | 上に小さく話題と見出し、その下に大きく結論の一文（左に主色の短い縦棒）、細い線で本文と分ける。下の帯は無く、本文が一番広い | 上の2段 19%・本文 62%（一番広い） | テンプレート1（`"conclusion": "header"`、標準の色 墨と藍） | ラベル・展開・問い・手順。合わない：帰結 |
| 結論タイトル | 上に小さく話題、その下に大きく結論の一文。下の帯は無し（結論を見出しにする形） | 上の2段 20%・本文 60% | テンプレート2（`"conclusion": "title"`、標準の色 藍） | ラベル・展開・問い・手順。合わない：帰結 |
| 細い左帯と副題 | 左端に主色の細い帯、大きなタイトルの下に結論の副題の1行。下の帯は無し | 左の帯 2%・上の2段 22%・本文 60% | テンプレート3（`"conclusion": "lead"`、標準の色 青緑） | ラベル・展開・問い・手順。合わない：帰結 |
| 下の帯 | 左上の縦棒とタイトル、下の帯に結論の1行（ゼミの基本の形） | 本文 53%・下の帯 10% | テンプレート4（`"conclusion": "band"`、標準の色 青） | どれでも（帰結が一番合う） |
| 上の帯 | 上の濃い帯にタイトル、下に「まとめ」の札つきの淡い帯 | 上の帯 14%・本文 53%・下の帯 10% | テンプレート5（`"conclusion": "band"`、標準の色 紺とオレンジ） | どれでも（帰結が一番合う） |
| 章のナビ | 上に章の並び（今の章を主色に）、その下にタイトル、下に線で挟んだ結論の1行（長い発表） | 章のナビ 5%・本文 52%・下の線の帯 10% | テンプレート6（`"conclusion": "band"`、標準の色 墨と山吹） | どれでも（帰結が一番合う） |
| 結論の囲み | 上に淡い帯（タイトルは中央）、下の帯は無く、結論は淡い色の囲みに（学会発表） | 上の帯 13%・本文 48%・結論の囲み 9% | テンプレート7（`"conclusion": "box"`、標準の色 生成りと山吹） | 塊1つ（帰結・ラベル・問いのどれか1つ）。塊は1つ |
| 左の淡い柱 | 左の 34% の淡い柱にタイトル・結論・短い要点、右に図を大きく（図が主役の枚） | 柱 34%（タイトル・結論・短い要点）・右 60%（図） | テンプレート8（`"conclusion": "column"`、標準の色 珊瑚） | ラベル・帰結・箇条（柱の中の短い要点）。合わない：展開・場合分け・式の注釈 |

どの構造でも、`deck.slide(題, summary="結論")` の summary が結論の置き場に入る（下の帯・囲み・結論の一文・副題・柱のタイトルの下）。結論の一文・副題が上にある構造（結論ヘッダー・結論タイトル・細い左帯と副題）では、`s.heading` の見出しは別の行にせず、タイトルの行の後ろに「／ 見出し」と足す（上が3段に重ならないように）。
下の帯の無い構造（結論ヘッダー・結論タイトル・細い左帯と副題・結論の囲み）では、保存のときに本文の塊を縦の中央に寄せる（上寄せのままだと下が大きく空く。`Deck(..., valign="top")` で上寄せのまま）。それでも本文の下から 1.6 in 以上空く枚は、描画の検査が「下が空いている」を出す：図を縦に大きく描くか、中身を足す。本文の場所は構造ごとに違うので、位置は `deck.area`（x・top・right・bottom・fig_x、柱のある構造は text_right）から決める。部品（s.cards・s.compare・s.pair など）は自動でその範囲に置く。柱のある構造では、横いっぱいの部品は右の白い所に置く。章のナビの構造では、`deck.slide(題, section="結果")` の章（省けば題）を上に並べ、今の章を主色にする。
「合う本文の形」から外れる形を構成案・設計メモの「本文の形」の列に書くと、check_outline・check_memo が △ を出す（テンプレートは構成案の `## オプション` の「テンプレート」か、build.py の `deck_options(..., name=)` から読む）。結論が上にある構造で帰結を避けるのは、本文の最後の「⇒ 赤字」が上の結論と重なるから。結論の囲みは本文が狭いので塊を1つに、左の淡い柱は横に広がる形が柱に入らない。
選び方：迷ったら テンプレート1（結論ヘッダー）。ゼミで下の帯に結論を置く形に慣れているなら 下の帯、学会発表は 結論ヘッダー・結論タイトル・結論の囲み、図が主役で文は短い要点だけの枚なら 左の淡い柱（柱の中は1行14字まで）、章の多い長い発表は 章のナビ。番号は見やすさの順（同じ中身で描き、名前を伏せて採点した順）。構造の名前でも選べる（`deck_options(P, name="結論の囲み")`、一覧の「テンプレート」の行に「結論の囲み」）。

## 4. 置き方の決まり（研究発表のデザインの手引きから）

- **矢印は主役ではない**。太く濃い矢印で目立たせない（カードの順序・循環は細い矢印）。テンプレートの .json の `"arrow": "thin"` で、展開・縦の結論の矢印も細くできる
- **囲みすぎない**。まとまりは余白で作り、枠は最小限。図形は塗りか線のどちらか一方だけに色を付ける（部品は塗りだけ）
- 1枚の中で図形の種類（四角・角丸・円）を混ぜない。角丸の丸みをそろえる。楕円で強調しない（注目の輪 `s.oval` は図の上の目印として別）
- 小見出しの横やそれより上に中身を置かない（中身は小見出しの右下）。揃えられる所は全部揃える（左端・上端）
- 文字と枠の縁を近づけない（部品は枠の内側に余白を取る）

参考：研究発表のユニバーサルデザインの手引き（伝わるデザイン：レイアウト・図解）、公開されたスライドの型の一覧（並列・比較・フロー・サイクル・ピラミッド・マトリクス・ベン図・ツリー・ビフォーアフターなど）、研究発表用のスライドテンプレートと研究室向けのスライド作成の解説、assertion-evidence（結論の一文を見出しに）の考え方。

## 5. 本人の組み方を数える（analyze_structure.py）

```bash
python <skill>/scripts/analyze_structure.py スライドテンプレート/           # フォルダの pptx を全部
python <skill>/scripts/analyze_structure.py 発表A.pptx 発表B.pptx --skip 3,7-9
```

本文の形ごとの枚の割合、結論の置き場、赤字のある枚の割合、1枚の文字の塊の数を出し、設定の一覧に書く1行
（`- 本文の形の割合: ラベル 47%、帰結 38%、展開 23%…`）を出す。**数えるのは手本にしたい枚だけ**：
古い・見にくいとユーザーが言う枚は `--skip` で外す（各デッキの1枚目は表紙として数えない）。
見た目の分析（analyze_template.py）と組み合わせると、見た目と組み方の両方が本人のデッキに近づく。
